📌 Prerequisites
• AWS account with billing enabled
• AWS CLI installed on your local machine (optional, but helpful)
• SSH client (built into macOS/Linux, use PuTTY on Windows)
• Basic command line familiarity

1 Provision AWS t3a Instance

Option A: AWS Console (Web UI)

  1. Log into AWS EC2 Console
  2. Click Launch Instance
  3. Configure:
    • Name: sq-server (or your choice)
    • AMI: Ubuntu Server 24.04 LTS (64-bit x86)
    • Instance Type: t3a.small (2 vCPU, 2 GB RAM — $12/mo)
    • Key Pair: Create new or use existing (download .pem file if new)
    • Network: Allow SSH (port 22) from your IP
    • Storage: 20 GB gp3 (default is fine for testing)
  4. Click Launch Instance
  5. Note the Public IPv4 Address (e.g., 44.248.235.76)

Option B: AWS CLI (Faster)

# Create security group allowing SSH
aws ec2 create-security-group \
  --group-name sq-server-sg \
  --description "SQ Server Security Group"

# Allow SSH from your IP (replace YOUR_IP with your actual IP)
aws ec2 authorize-security-group-ingress \
  --group-name sq-server-sg \
  --protocol tcp \
  --port 22 \
  --cidr YOUR_IP/32

# Launch instance (replace KEY_NAME with your key pair name)
aws ec2 run-instances \
  --image-id ami-0e2c8caa4b6378d8c \
  --instance-type t3a.small \
  --key-name KEY_NAME \
  --security-groups sq-server-sg \
  --block-device-mappings '[{"DeviceName":"/dev/sda1","Ebs":{"VolumeSize":20}}]' \
  --tag-specifications 'ResourceType=instance,Tags=[{Key=Name,Value=sq-server}]'
💡 Tip: Find your IP with curl ifconfig.me or visit whatismyipaddress.com

2 Connect to Your Instance

# Make sure your key has correct permissions
chmod 400 /path/to/your-key.pem

# SSH into the instance (replace with your IP and key path)
ssh -i /path/to/your-key.pem ubuntu@YOUR_INSTANCE_IP
✅ Success looks like:
You see a prompt like ubuntu@ip-172-31-x-x:~$

3 Update Ubuntu & Install Dependencies

# Update package lists
sudo apt update

# Upgrade existing packages
sudo apt upgrade -y

# Install build essentials
sudo apt install -y build-essential pkg-config libssl-dev git curl

This takes ~3-5 minutes. Wait for it to complete.

4 Install Rust & Cargo

SQ is written in Rust. You need the Rust toolchain:

# Install Rust via rustup (official installer)
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh

# When prompted, choose option 1 (default installation)
# Then press Enter

# Load Rust into current shell
source $HOME/.cargo/env

# Verify installation
rustc --version
cargo --version
✅ Success looks like:
rustc 1.x.x
cargo 1.x.x

5 Install SQ from Source

Option A: Install from Crates.io (Recommended)

# Install SQ from the official Rust package registry
cargo install sq-server

# Verify installation
sq --version

Option B: Build from GitHub Source

# Clone the SQ repository
git clone https://github.com/wbic16/SQ.git
cd SQ

# Build in release mode (optimized, ~2-3 minutes)
cargo build --release

# The binary is now at: target/release/sq
# Optional: copy to /usr/local/bin for system-wide access
sudo cp target/release/sq /usr/local/bin/

# Verify
sq --version
✅ Success looks like:
SQ 0.5.x

6 Configure SQ

Create a basic configuration file:

# Create config directory
mkdir -p ~/.sq

# Create config file
cat > ~/.sq/config.toml << 'EOF'
# SQ Server Configuration

[server]
host = "0.0.0.0"        # Listen on all interfaces
port = 1337             # Default SQ port

[storage]
path = "~/.sq/data"     # Where phext scrolls are stored

[auth]
enabled = false          # Disable auth for local testing
# token = "your-secret-token-here"  # Uncomment for production

[limits]
max_scroll_size_mb = 10
max_coordinates = 1000000
EOF

# Create storage directory
mkdir -p ~/.sq/data
⚠️ Security Note: This config disables authentication for local testing. For production, enable auth and use a strong token. See SQ Security Docs.

7 Start SQ Server

Quick Test (Foreground):

# Run SQ in foreground (Ctrl+C to stop)
sq serve --config ~/.sq/config.toml

You should see:

🗄️  SQ Server v0.5.x starting...
📡 Listening on 0.0.0.0:1337
✅ Ready to serve phext coordinates

Production Setup (Background with systemd):

# Create systemd service file
sudo tee /etc/systemd/system/sq.service > /dev/null << 'EOF'
[Unit]
Description=SQ Phext Server
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/home/ubuntu
ExecStart=/usr/local/bin/sq serve --config /home/ubuntu/.sq/config.toml
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
EOF

# Reload systemd
sudo systemctl daemon-reload

# Enable SQ to start on boot
sudo systemctl enable sq

# Start SQ service
sudo systemctl start sq

# Check status
sudo systemctl status sq
✅ Success looks like:
Active: active (running) in green

8 Store Your First Coordinate

Use the REST API to write text to a phext coordinate:

# Store "Hello, Phext!" at coordinate 1.1.1/1.1.1/1.1.1
curl -X PUT http://localhost:1337/scroll/1.1.1/1.1.1/1.1.1 \
  -H "Content-Type: text/plain" \
  -d "Hello, Phext! This is my first scroll at coordinate 1.1.1/1.1.1/1.1.1"
✅ Success looks like:
{"status":"ok","coordinate":"1.1.1/1.1.1/1.1.1","bytes_written":67}

🔒 Bonus: SSL Setup with nginx + Let's Encrypt

For production, serve SQ over HTTPS:

# Install nginx and certbot
sudo apt install -y nginx certbot python3-certbot-nginx

# Configure nginx as reverse proxy
sudo tee /etc/nginx/sites-available/sq << 'EOF'
server {
    listen 80;
    server_name your-domain.com;
    
    location / {
        proxy_pass http://localhost:1337;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
EOF

# Enable site
sudo ln -s /etc/nginx/sites-available/sq /etc/nginx/sites-enabled/
sudo nginx -t
sudo systemctl reload nginx

# Get SSL certificate (replace your-domain.com and your-email)
sudo certbot --nginx -d your-domain.com --email your-email --agree-tos

Now access SQ at https://your-domain.com

🔧 Troubleshooting

  • SQ won't start: Check logs with sudo journalctl -u sq -f
  • Connection refused: Make sure security group allows port 1337
  • Permission denied: Ensure ~/.sq/data is writable by ubuntu user
  • Build fails: Run sudo apt install build-essential pkg-config libssl-dev
